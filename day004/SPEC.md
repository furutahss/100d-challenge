# 画像サイズコンバータ 仕様書

## 1. 概要

画像ファイルをサーバーへ送信せず、利用者のブラウザ内で変換するWebアプリケーション。複数ファイルをまとめて処理でき、次の2モードを提供する。

- ファイルサイズ指定モード：画像の縦横ピクセル数を維持したまま、画質を調整して目標ファイルサイズ以下を目指す。
- 画像サイズ変更モード：画質設定を維持し、指定した縦横ピクセル数に画像をリサイズする。

## 2. 技術構成

- Next.js（App Router、静的エクスポート / SSG）
- TypeScript
- Tailwind CSS
- SCSS（コンポーネント固有の装飾）
- ブラウザ標準の File API / Canvas API
- JSZip（一括ダウンロード用）
- Vitest + Testing Library（TDD・ユニットテスト）

変換処理はすべてクライアントサイドで実行し、画像を外部サービスへ送信しない。

## 3. 入力

### 3.1 ファイル追加

- ファイル選択とドラッグ＆ドロップで画像を追加できる。
- 複数ファイルの同時選択・追加に対応する。
- 対象はブラウザがデコード可能な一般的な画像形式（JPEG、PNG、WebP、GIF、BMP、AVIF等）とする。
- アニメーション画像は先頭フレームを静止画として処理する。
- 読み込み不能なファイルは処理対象にせず、理由を表示する。

### 3.2 変換対象形式

- 出力形式は JPEG / PNG / WebP から選択する（初期値：元画像と同じ形式。ただし対応外形式は PNG）。
- JPEG出力時に透過を含む画像は白背景で合成する。
- PNGはブラウザ仕様により画質パラメータが効かないため、ファイルサイズ指定モードでは目標サイズに収められない場合がある。その場合は結果と注意を表示する。

## 4. モードと変換仕様

### 4.1 ファイルサイズ指定モード

- 目標サイズを KB または MB で入力する（正の数値）。
- 元画像の縦横ピクセル数は変更しない。
- JPEG / WebP は二分探索で画質を調整し、目標サイズ以下の中で可能な限り高画質な結果を生成する。
- 最低画質でも目標に届かない場合は、最低画質の結果を生成して「目標サイズに到達できませんでした」と表示する。
- 元ファイルがすでに目標以下の場合も、変換結果を生成する。

### 4.2 画像サイズ変更モード

- 幅・高さをピクセル単位で入力する（正の整数）。
- 「縦横比を維持」を初期状態で有効にし、片方を変更するともう片方を自動計算する。
- 縦横比維持を無効にした場合は、幅・高さをそれぞれ指定できる。
- 画質は変更しない。出力形式とエンコーダーの都合による再エンコードは行うが、JPEG / WebPの品質値は最高品質を使う。
- EXIFの向きを考慮した見た目の向きでリサイズする。EXIFなどのメタデータは出力時に保持しない。

## 5. 画面・操作

画面はHEROを置かず、次の要素を上から順にシンプルに配置する。

1. アプリ名と「ブラウザ内で処理・アップロード不要」の補足
2. 画像追加エリア
3. モード切替、モード別設定、出力形式選択
4. 「変換する」ボタン
5. 処理結果一覧
   - 元ファイル名、元と変換後のファイルサイズ、元と変換後の寸法
   - サムネイル、状態・注意メッセージ、個別ダウンロードボタン
6. 全結果が成功した場合に表示するZIP一括ダウンロードボタン

- 各ファイルは変換前に一覧から削除できる。
- 変換中は実行ボタンを無効化し、進捗（処理済み件数）を示す。
- 変換結果を追加画像の前に明確にリセットできる。
- モバイル画面では設定項目と結果カードを縦に並べる。

## 6. ダウンロード

- 個別ダウンロードは各変換結果をそのまま保存する。
- 一括ダウンロードは成功結果のみをZIPにまとめて保存する。
- 出力ファイル名は元のベース名にモードを表す接尾辞を付与する。
  - ファイルサイズ指定：`{元名}-compressed.{拡張子}`
  - 画像サイズ変更：`{元名}-{幅}x{高さ}.{拡張子}`

## 7. 非機能要件・制約

- ブラウザ対応は最新のChrome、Safari、Firefox、Edgeを対象とする。
- すべての画像データはブラウザのメモリ内で処理する。
- メモリを解放するため、削除・リセット・画面離脱時に生成済みObject URLを破棄する。
- 大きな画像や多数の画像ではブラウザのメモリ制限により失敗する可能性がある。失敗したファイルは他のファイルの処理を妨げず、エラーを個別表示する。
- 静的エクスポートの成果物だけでホスティング可能とする。

## 8. テスト方針（TDD）

- 実装前に対象関数の失敗するテストを書く。
- 単体テスト対象：入力値検証、サイズ単位変換、縦横比計算、出力ファイル名、画質探索の分岐、結果の状態管理。
- コンポーネントテスト対象：モード切替、入力エラー、ファイル削除、変換中の無効化、ダウンロード操作の表示条件。
- CanvasやブラウザダウンロードAPIはテストでモックし、実ブラウザ相当の動作はproduction build後に手動確認する。

## 9. favicon

- 画像のフレームと対角方向のリサイズ矢印を組み合わせた、アプリ内容が伝わるfaviconを作成する。
- SVGをベースに、Next.jsのアプリアイコンとして反映する。
